# Дебиторка — локальное приложение Битрикс24

## Обзор

Локальное приложение для портала Битрикс24 `<portal>.bitrix24.ru`, формирующее сводный отчёт по счетам («Дебиторка») в разрезе контактов и в разрезе ответственных сотрудников. Приложение оформлено в виде ZIP-архива и устанавливается через раздел «Приложения → Разработчикам → Другое → Локальное приложение». Закрывает функциональный пробел BI-конструктора Битрикс24, который не позволяет задать одновременно два независимых диапазона дат (срок оплаты и фактическая дата оплаты).

## Основные функции

- Сводная таблица по контактам с пятью колонками:
  1. ФИО контакта (кликабельная ссылка, открывающая карточку контакта в слайдере Битрикса).
  2. Должен всего — `SUM(opportunity)` по всем активным счетам контакта.
  3. Оплачено — `SUM(opportunity)` по счетам со стадией `DT31_5:P` («Оплачен»).
  4. Просрочено — `SUM(opportunity)` по счетам со стадией ≠ `DT31_5:P` и `closedate < сегодня`.
  5. Остаток к оплате — `SUM(opportunity)` по счетам со стадией ≠ `DT31_5:P`.
- Две вкладки над таблицей: «Дебиторка по клиентам» (строка на контакт) и «Дебиторка по сотрудникам» (те же колонки, группировка по `assignedById` счёта, первая колонка «Сотрудник» — простой текст без ссылки; уволенные — «(уволен)», без ответственного — «Без ответственного»). Фильтры общие; вкладки переключаются без перезагрузки данных; обе считаются по одним и тем же счетам (с `contactId`), поэтому «Итого» совпадают. Вкладка в URL не сохраняется.
- KPI «% сбора дебиторки» вверху панели фильтров = Оплачено / Должен всего по текущему фильтру, с подписью «Оплачено X из Y»; при нулевой сумме — «—».
- Фильтры:
  - Ответственный (за **счёт**, multi-select). В списке — только ответственные счетов за выбранный период (после фильтров по сроку и дате оплаты), включая уволенных; список обновляется после каждой загрузки отчёта. Применяется на клиенте.
  - Срок оплаты от/до (`closedate`).
  - Дата оплаты от/до (`ufCrmSmartInvoiceDatePay`).
  - По умолчанию `closedate` = первое..последнее число текущего месяца.
- Серверная пагинация и параллельная загрузка через `BX24.callBatch`.
- Клиентская агрегация и сортировка (по умолчанию — по ФИО asc).
- Пагинация по 100 строк на страницу с индикатором «N из M»; при смене страницы — прокрутка к началу таблицы.
- Таблица без собственной прокрутки — прокручивается вся страница; шапка таблицы липнет к верху окна, строка «Итого» — к низу. На ширине ≤ 720 px таблица прокручивается по горизонтали.
- Закреплённая строка «Итого» по всем отфильтрованным контактам (не по странице).
- Раскладка: на ширине ≥ 1200 px фильтры — справа столбиком (320 px, остаются на виду при прокрутке), таблица — слева на всю оставшуюся ширину; уже 1200 px — фильтры сверху (4 / 2 / 1 колонки).
- Экспорт XLSX активной вкладки по всем её строкам плюс строка «Итого» (`debt_clients_YYYY-MM-DD.xlsx`, лист «По клиентам» / `debt_staff_YYYY-MM-DD.xlsx`, лист «По сотрудникам»).

## Технологический стек

- **Язык программирования:** Vanilla JavaScript (ES2020), без сборщика и фреймворков.
- **Платформа:** Битрикс24 JS SDK (`BX24.callMethod`, `BX24.callBatch`, `BX24.openSlider`) через `https://api.bitrix24.com/api/v1/`.
- **REST API:** `crm.item.list` (entityTypeId=31, Smart Invoice 2.0), `crm.contact.list`, `user.get`; классический `batch`.
- **Vendor-библиотеки (загружаются локально из `vendor/`):**
  - `xlsx.full.min.js` (SheetJS) — экспорт XLSX; грузится лениво, при первом экспорте.
  - `flatpickr` + RU-локаль — поля выбора даты.
- **Сборка:** отсутствует. Артефакт — ZIP с `index.html`, `app.js`, `styles.css`, `vendor/*`.
- **Dev-режим:** `fetch` к webhook из `.env` (`B24_WEBHOOK_URL`) для отладки вне портала.
- **Хранилище состояния:** только клиент (in-memory + параметры URL для сохранения фильтров).

## Архитектурные заметки

- **Тип приложения:** статичное локальное (zip-архив, без серверного бэкенда и собственного хостинга).
- **Двухрежимный API-клиент:** в портале — `BX24.*`, в dev — `fetch` к webhook. Один общий слой `apiClient.callMethod / callBatch`, разводка по наличию `window.BX24`.
- **Поток данных:**
  1. `BX24.init` → рендер UI фильтров и вкладок → первичная загрузка отчёта.
  2. При применении фильтров: `crm.item.list` (filter: даты + `!=stageId:DT31_5:D`, без `@assignedById`) с распараллеливанием через `BX24.callBatch` (1 batch ≈ 11 страниц по 50).
  3. Постфильтр `ufCrmSmartInvoiceDatePay` (если задан); счета без `contactId` отбрасываются. Из оставшихся — список ответственных периода; затем фильтр по выбранным ответственным на клиенте.
  4. Параллельно: `crm.contact.list (ID:[...])` по 50 ID в команде, одним `callBatch` → ФИО контактов; `user.get (FILTER: {ID:[...]})` → ФИО и признак `ACTIVE` ответственных (включая уволенных).
  5. Агрегация в JS: `Map<contactId, …>` и `Map<assignedById, …>` (`{amount, paid, overdue, remain}`) + KPI «% сбора» + рендер активной вкладки и кнопки XLSX.
- **Семантика «Ответственный»:** фильтр берётся из `crm.item.list.assignedById` (ответственный за счёт) и применяется на клиенте, потому что список ответственных строится из всех счетов периода. URL-параметр `assignedById` сохраняет имя; смысл сменился с «ответственный за контакт» на «ответственный за счёт». Аудитория = один пользователь → миграция URL не требуется.
- **Фильтр-синтаксис:** `crm.item.list` принимает операторы (`>=closedate`, `<=closedate`, `!=stageId`, `@…`) ТОЛЬКО при `Content-Type: application/json` (для прямых curl-запросов). Внутри портала через `BX24.callMethod` сериализация корректна.
- **Бизнес-правило `is_paid`:** строго `stageId == 'DT31_5:P'`. Любая другая стадия (включая `DT31_5:N`, `DT31_5:S`, `DT31_5:UC_*`) — счёт в работе. Стадия `DT31_5:D` («Не оплачен») отсекается серверным фильтром.
- **Производительность:** портал маленький — ~1 740 счетов всего, ~5–15 за типичный месяц (данные в основном 2021–2025). Месяц — один вызов `crm.item.list`, год (~400 счетов) — 1 вызов + 1 batch. Узких мест по объёму нет; батчи выполняются последовательно (REST-квота ~2 req/sec).

## Нефункциональные требования

- **Объём поставки:** ZIP ≤ 500 KB (включая vendored xlsx и flatpickr).
- **Производительность отчёта:** ≤ 5 секунд для любого периода (весь портал — ~1 740 счетов).
- **Развёртывание:** один HTML, чистый JS, без сборки. `unzip`, открыл `index.html` (с моком webhook) — работает.
- **Логирование:** консольное (`console.log` / `console.warn` / `console.error`) с префиксами модулей. В dev-режиме — verbose, в портале — только ошибки.
- **Обработка ошибок:** все `BX24.callMethod` / `fetch` обёрнуты в `try/catch`. Ошибки REST показываются пользователю в баннере над таблицей, технические детали — в консоль.
- **Безопасность:**
  - `.env` с `B24_WEBHOOK_URL` НЕ попадает в ZIP-артефакт (включить в `.gitignore` и в исключения упаковки).
  - Никаких хардкод-токенов в коде. В портале аутентификация проксируется через `BX24.*`.
  - Никаких внешних CDN на проде — все vendor-зависимости лежат локально в `vendor/`.
- **Целевая аудитория:** один пользователь-руководитель, размещение в общем разделе «Приложения» портала.
- **i18n:** только русский язык интерфейса.
